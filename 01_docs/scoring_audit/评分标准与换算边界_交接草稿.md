# 评分标准与换算边界（Dot 交接稿）

审计日期：2026-11-12。以下是已有证据的整理，不是新的平台实测、也不是官方 checker 源码。

## 先区分三种“换算”

1. **同一用例、同一真实电机轨迹，用正确公式重新计分：可以。** 要有数组的真实主峰位置和完整实际查询轨迹；或完整数组使得主峰可独立计算。没有必要把整个数组交给候选算法，数组只能在离线 checker 侧使用。
2. **同一策略多一次最后原位查询，用两次平台分数的差解出正分人数：有条件可以。** 必须确认源码/顺序匹配，物理轨迹只多该查询，所有原正分的新增 Q 仍小于 200。已验证 12/13 满足此条件。
3. **把任意合成集总分乘一个系数，准确换成固定官方102例总分：不可以。** 当前没有官方102例完整曲线，也没有新候选在官方每例的完整真实轨迹。已知峰位多重集合不等于完整数组，不足以复现算法所看到的值或决定它的轨迹。任何平均分×102、归一比例或历史拟合都只能是统计估计，不能称精确换算。

因此，应把便携工具的输出称作“本地按平台校准模型计分”，不要称作“已预测官方分数”。实际官方总分仍必须提交得到。

## 特别警告：原题 PDF 的字面公式与本研究平台校准模型不同

- 原题 PDF 第3页及第4页样例使用每次振荡扣 **1** 分（R1）；样例得分写为 **2984**。原 PDF 应原封保存，不应改字来消除矛盾。
- 旧 `competition_analysis/evaluator.py` 和原包 `information_reset_20261104/support/harness.py:score()` 也按 R1 计分。这些旧本地“总分”不能直接混入最新 R30 结果。
- 本研究按已采信的平台探针校准模型使用每次振荡扣 **30** 分（R30）。它不是从 PDF 原文直接读出的常数，也不是对官方 checker 源码的审阅结论。
- 交接后若换了赛题、评测批次或平台版本，须重新确认该模型仍适用；不要把两者差异当作已不存在。

## R30 单例计分定义

电机初始位置为0；真实查询轨迹为 `x1,...,xQ`。下标均为0-based。

- `p`：原始数组全局最大值的下标；最大值并列时，先取距离 `(N−1)/2` 最近者，再取较小下标。可用键 `(-value[i], abs(2*i-(N-1)), i)`。
- `Q`：实际向 checker 发出的查询次数，含重复查询和末次真实返回查询。读取程序内部缓存不是查询，不移动电机。
- `M = |x1−0| + Σ|xt−x(t−1)|`：总运动距离。
- `R`：相邻非零移动方向之间的反转数。首次非零移动不算反转；原位查询不清除此前方向。原题没有明确独立描述“零移动方向”的细节，本项目实现按上述规则，历史诊断亦依赖此规则。
- `O = max(0, max(x1,...,xQ)−p)`：曾到达的最右位置超过真实主峰的距离。最后回到p也不能消除已发生的O。
- `d = |xQ−p|`：末次真实查询位置误差。`DONE` 没有位置参数，不能用内存变量 best 当作最终位置。

对协议正确且资源运行合规的用例：

```text
如果 d>3 或 Q>=200 或 R>=7 或 O>=200：单例0分
否则 S30 = max(0, 3000 - 200*d - Q - M - 30*R - O)
```

平台总分为102例单例分相加，理论上限306000。合法零分与整份提交失败是两回事。

### 协议/运行检查独立于公式

原题要求单例10秒、512MB；ASCII协议行不超过64字节；下标在[0,N−1]；每次输出刷新；输出DONE后正常退出且不再输出其他协议内容。越界、非法输出、DONE缺失/后续输出、非零退出码、超时等不能伪装成普通单例0分而继续报告“平台有效总分”。

原题允许调试信息写stderr；本项目回归工具额外要求stderr为空，是更严格的本地验证约定，不应把所有stderr输出笼统说成官方协议错误。完整批量数组适配器也不能替代真实交互刷新、超时、进程退出和内存验证。

## 旧R1记录如何换成R30

如果旧记录的**输入、主峰规则、真实轨迹、硬门槛和Q/M/R/O/d定义完全相同**，仅振荡罚分从1改30，则每例严格有：

`S30_i = max(0, S1_i - 29*R_i)`。

这一等式包含截零：旧R1为0的用例在其他条件相同情况下仍为0；旧R1正分可能在R30下归零。若还有硬阈值差异或协议差异，应从轨迹重算，不能套该捷径。

总分应逐例转换后求和：

`Total30 = Σ max(0, S1_i - 29*R_i)`。

**不能通常使用 `max(0, Total1 - 29*ΣR_i)`。** 截零在每例上发生，不是只在总分上发生。也不能仅拿一个旧总分（无逐例R、无轨迹）声称已经恢复了新总分。

本轮对10000组随机指标元组验证了上述逐例恒等式；此为算术检查，不是新曲线/新平台实测。

## 已验证的官方分数差分，不是“模拟总分到平台”的回归系数

如果计数版只在最后加1次真实原位查询，原版每条Q≤198，则计数版Q≤199，M/R/O/d完全不变：

- 每个原正分恰减1（即使1分变0，也贡献差值1）。
- 每个原零分仍零。
- `正分人数 P = 同策略性能版总分 - 同策略计数版总分`。

具体12/13：`149485−149405=80`正分、22零分。它不能用147097减149405；计数对照必须是同一个性能策略。

相比147097也是80正分，只说明净人数相同，不说明成功集合相同。可救回r同时丢失r，r尚未知。新版精确命中数量也未知；原147097的79至80精确下界不可继承。

其他诊断（早/晚群载体、弱信号权重、精确下界）也必须绑定各自源码SHA、父载体分数和人数编码。其分数不能作为算法性能排名，不能把其公式移植到任意新main.cpp。
